# codeguide-multitenant-ticketing App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new user visits the application, they land on a simple marketing page that invites them to either log in or sign up. From here, they can click a prominent button to begin the registration process. The sign-up form is powered by Clerk, allowing users to register with their email and password or choose a social login option such as Google or GitHub. If the user selects email and password, they enter their name, email, and create a password before verifying their email address by clicking the link sent to them. If they choose a social login, Clerk redirects them to the provider’s consent screen and returns them to the application once authentication succeeds. After verifying their email or completing social login, new users are prompted to create their first tenant, which in this context is an organizer profile for managing events. They name their organizer account and complete basic details. For returning users, they can sign in by entering their credentials on the sign-in page or by clicking a social login button. Clerk maintains the session and issues a JWT for API authentication. Users can sign out at any time via a logout link in the navigation menu. If a user forgets their password, they can click “Forgot password,” enter their email, and receive a reset link that allows them to choose a new password. Once the password is reset through the secure link, they can log in normally.

## Main Dashboard or Home Page

After signing in, users arrive at the main dashboard. At the top is a header containing the application logo, the name of the currently selected tenant (organizer), and a profile menu where they can access account settings or log out. On the left is a collapsible sidebar containing links to core sections: Event Management, Ticket Sales, Gate Logs, and AI Assistant. The central area of the dashboard first shows a Tenant Selector component that lists all organizers the user has created or joined. Selecting a tenant filters all subsequent pages to that tenant’s scope. Below the selector is a snapshot of upcoming events for that organizer, presented as cards with event name, date, and a quick “View details” button. The footer includes version information and a support link. From this home page, the user can navigate to create new events, view ticket purchase statistics, validate tickets at entry points, or call AI tools to generate event descriptions.

## Detailed Feature Flows and Page Transitions

When the user chooses to create an event, they click “Event Management” in the sidebar and land on an event list page. There, they click a “New Event” button to open a form where they fill out event details such as title, date, location, and ticket pricing. The form uses React Hook Form and Zod validation to ensure all required fields are filled and correctly formatted. Upon submission, the front end calls the `POST /api/tenants/[tenantId]/events` API route. The route validates the input, inserts a new record into the Supabase `events` table, and returns the created event data. The user is redirected to the event details page, which shows event information alongside a “Sell Tickets” button. Clicking this button opens a ticket purchase interface.

In the ticket purchase view, external users visiting the public event page can select ticket quantities. When they click “Purchase,” the client submits data to the `POST /api/tenants/[tenantId]/tickets/purchase` endpoint. The API route validates the request, calls Stripe’s one-time Checkout Session creation, and returns a session ID. The front end then redirects the user to Stripe’s hosted checkout page. After the user completes payment, Stripe triggers a webhook to `app/api/webhooks/route.ts`. The webhook handler verifies the event, updates the `payments` table in Supabase, creates a `tickets` record, calls the QR code generator utility to produce a QR code string, and uses a PDF generation utility to assemble a ticket PDF with the QR embedded. The webhook response includes a URL to the ticket PDF stored in Supabase Storage. Meanwhile, the user sees a confirmation page with a link to download their ticket.

For on-site validation, staff open the Gate Scanner page from the sidebar. This page uses a React QR reader component to capture codes from the device camera. When a QR is scanned, the front end sends the scanned ticket ID to the `POST /api/tenants/[tenantId]/tickets/[ticketId]/validate` endpoint. The API checks the ticket status and if valid, marks it as used by inserting a record into the `gate_logs` table with timestamp, scanner ID, and validation result. The response indicates success or failure. The front end displays a green “Valid” message or a red “Invalid or Already Used” message. Users can view a paginated list of gate logs on the Gate Logs page, which retrieves logs via `GET /api/tenants/[tenantId]/gate_logs` and shows them in a table with filters for date, scanner, and outcome.

Advanced workflows include using the AI Assistant link. Clicking it opens a panel where the user types a prompt such as “Create a catchy event description for a summer music festival.” The front end sends this to the OpenAI API through an internal proxy route at `app/api/ai/generate`. The AI utility formats the prompt, calls OpenAI, and returns generated text. The response populates a text box where the user can copy the generated content back into the event editor.

## Settings and Account Management

Users access account management by clicking their profile avatar in the header. This opens a settings page where they can update personal details such as name, email, and password. The form for changing password requires the current password and the new password twice. On saving, the front end calls Clerk’s user management API to update credentials. Under a separate Billing tab, users see current invoice history and can update their default payment method using a Stripe-hosted payment method form. When a new card is added, the front end requests a Stripe SetupIntent and uses Stripe Elements to securely collect card details, then submits the token to the `POST /api/billing/payment-method` route. From settings, a user can navigate back to the main dashboard by clicking the logo or the “Dashboard” link in the sidebar.

## Error States and Alternate Paths

If users submit invalid data, such as missing required fields in the event creation form or an incorrectly formatted email in sign-up, the form immediately highlights the error and displays a descriptive message next to the field. If the API returns a server error, a banner appears at the top of the page with a friendly explanation and a retry button. During ticket purchase, if the Stripe checkout session fails or is canceled, the user is redirected back to the purchase page with an alert stating that the payment did not complete and inviting them to try again. If connectivity is lost while interacting with any page, a toast notification appears indicating offline status and an automatic retry is attempted when the network returns. When scanning tickets, if the system cannot reach the validation endpoint, the scanner shows a warning and allows the staff to try again manually. If a user attempts to access a tenant they do not belong to, the middleware returns a 403 response and the front end shows an “Access Denied” page with a link to select a different tenant or contact support.

## Conclusion and Overall App Journey

A user’s journey begins at the landing page, where they register via Clerk and set up their first organizer profile. They then use the main dashboard to manage events, create or edit upcoming shows, and publish ticket sales. External customers visit public event pages, purchase tickets through Stripe, and receive a PDF ticket with a QR code. On the day of the event, staff use the Gate Scanner to validate entries and log scans. Organizers monitor sales and attendance in real time, and they can call on AI features to streamline content creation. Throughout this flow, the application ensures tenant data isolation with Supabase RLS, secure authentication with Clerk, and reliable payment handling with Stripe. From sign-up through everyday operations, every key action connects smoothly to the next, delivering a complete multi-tenant ticketing experience.
